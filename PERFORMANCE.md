# Анализ производительности и оптимизации

## Структура сайта

- **React (Vite)**: оболочка — один корневой компонент `App`, рендер разметки (loading, canvas, кнопки, мобильная навигация). Скрипты `about.js` и `script.js` подключаются динамически.
- **script.js (~5900 строк)**: основная логика — canvas, точки, загрузка изображений, режимы (selection, filter, connection, index), мобильная навигация, обработчики событий.
- **Canvas**: один 2D canvas на весь экран; каждый кадр вызывается `draw()` в цикле `requestAnimationFrame(animate)`.
- **Изображения**: загрузка с ограничением по количеству (`IMAGE_LOAD_CONCURRENCY`), кэш в `imageCache`, при необходимости используется `img.decode()`.

## Что уже оптимизировано в коде

- Кэш «mobile» в `draw._isMobileCached`, сброс при resize.
- Плавное обновление мыши только когда не dragging: `smoothMouseX += (targetMouseX - smoothMouseX) * 0.1`.
- Сетка фона через `CanvasPattern` (`getGridPattern()`), а не отрисовка линий каждый кадр.
- Один общий контекст для измерения текста (tempCanvas) в `positionFilterButtons`.
- Resize обрабатывается через один listener с `requestAnimationFrame` (в `runAppInit`): один rAF на resize, затем `resizeCanvas()`, инвалидация кэша, `generatePoints()`.
- Кэш DOM: `cachedBackButton`, повторное использование элементов в `createProjectAboutElements`.

## Внесённые оптимизации (без смены функционала)

1. **Progress bar**: длина уменьшена на 1/3 (260 → 174px), прозрачность 50% (трек и заливка).
2. **Убран дублирующий resize**: раньше были два `window.addEventListener('resize', ...)` — один вызывал только `resizeCanvas()`, второй (в runAppInit) — rAF + resizeCanvas + generatePoints. Оставлен один путь: начальный вызов `resizeCanvas()` при загрузке и один listener в runAppInit с rAF.
3. **Пауза анимации при скрытой вкладке**: в `animate()` вызов `draw()` выполняется только если `!document.hidden`. Цикл rAF продолжает крутиться, но отрисовка и тяжёлая логика в `draw()` не выполняются — меньше нагрузка на CPU и батарею.
4. **Throttle document mousemove**: глобальный `document` mousemove при уходе с canvas (очистка hover) ограничен по частоте (не чаще раза в 100 ms), чтобы не обрабатывать каждый событие при движении мыши по странице.

## Рекомендации для дальнейшей оптимизации

- **Сжатие и кэш скриптов**: `script.js` большой; уже используется сжатие (gzip/brotli) на сервере и кэш браузера. При необходимости — разбить на chunks (например, мобильная навигация/логика отдельно).
- **Изображения**: уже есть ограничение одновременной загрузки и опция `decoding="async"`; при желании можно добавить низкое разрешение/placeholder для первых кадров.
- **Canvas**: при очень большом количестве точек можно рассмотреть отсечение по видимой области (culling) и отрисовку только видимых; сейчас все точки проходят через draw.
- **События**: `handleMouseMove` / `handleTouchMove` на canvas вызываются часто; тяжёлые операции в них минимизированы (есть `getBoundingClientRect`), при необходимости можно троттлить по rAF.
- **Мобильная навигация**: пересчёт линий и позиций при resize уже в rAF; при желании можно кэшировать результат `drawMobileNavLines` до следующего resize.

Функциональность при описанных изменениях не менялась.
