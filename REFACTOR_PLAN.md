# Анализ кода и план рефакторинга (Repository pattern)

## Анализируемые файлы
- **script.js** — основная логика приложения (~5579 строк)
- **about.js** — константа `ABOUT_TEXT` (текст «We are»)

---

## Code smells (проблемы текущего кода)

### 1. Огромный монолит
- Вся логика в одном файле: canvas, загрузка изображений, фильтры, мобильное меню, анимации, события, режимы (filter, connection, index, we-are).
- Сотни глобальных переменных (`let`/`const` на верхнем уровне): `points`, `imageCache`, `cameraPanX`, `isFilterMode`, `alignedEmojiIndex`, `mobileAutoLines` и т.д.
- Сложно тестировать и менять одну часть без риска сломать другую.

### 2. Жёсткая привязка к данным и источникам
- **Список изображений**: массив `imagePaths` захардкожен в script.js (~290 строк). Добавление/удаление картинок требует правки кода.
- **Текст «We are»**: глобальная константа `ABOUT_TEXT` из about.js; script.js обращается к ней как `typeof ABOUT_TEXT !== 'undefined'`.
- **about.txt проектов**: прямой `fetch(\`${encodedPath}/about.txt\`)` внутри `loadAndDisplayAboutText`. Формат (парсинг по `#`, name/About) зашит в нескольких местах (parseAndDisplayAboutText, parseAndDisplayMobileAboutText).

### 3. Смешение слоёв
- **Данные и логика**: путь к папке `"Imgae test "` и структура папок зашиты в коде; нет абстракции «источник списка изображений».
- **Доступ к данным и UI**: загрузка картинок, fetch about.txt и отображение (DOM) переплетены в одних и тех же функциях.
- **Нет явного слоя «репозиторий»**: код сам решает, откуда брать список картинок и текст about, и как их загружать.

### 4. Прямая работа с DOM
- Множество `document.getElementById(...)`, `document.createElement`, манипуляции `style`, `classList` по всему коду.
- Нет разделения: «где мы получаем данные» и «где мы обновляем экран».

### 5. Дублирование и хрупкий парсинг
- Парсинг about.txt повторяется (desktop vs mobile), логика извлечения name/About и полей (project, client, studio, year и т.д.) размазана по функциям.
- Один источник правды для «списка изображений» отсутствует: images.js не используется, актуальный список только в script.js.

### 6. Отсутствие интерфейсов для данных
- Невозможно подменить источник изображений (например, API или другой формат папок) без правок по всему script.js.
- Невозможно подменить источник текста «We are» или about проектов без поиска по всему файлу.

---

## План рефакторинга в 3 шага (без поломки функциональности)

### Шаг 1: Ввести репозитории данных (Data layer)

**Цель:** Вынести все операции «получить данные» в отдельные объекты-репозитории. Остальной код не должен знать, откуда именно приходят данные (файлы, API, константы).

- **ImageRepository**
  - Методы: `getAllPaths()`, `getPathsByFolder(folderPath)` (или аналог для фильтра по папке).
  - Внутри репозиторий может читать тот же массив путей или в будущем — конфиг/API. Сейчас — обёртка над текущим `imagePaths` (или над данными, вынесенными в отдельный модуль/конфиг).
  - Загрузка одной картинки по пути может остаться в сервисе/хелпере, но «какие пути показывать» решает только репозиторий.

- **AboutRepository**
  - Методы: `getStudioAboutText()` — возвращает строку для блока «We are» (сейчас из about.js / ABOUT_TEXT).
  - `getProjectAbout(folderPath)` — асинхронно возвращает сырой текст или уже распарсенную структуру `{ name, aboutText, fields }` для папки проекта (внутри — тот же `fetch(…/about.txt)` и парсинг).
  - Всю логику парсинга about.txt (по `#`, по полям project/client/studio/year) сосредоточить внутри репозитория или одного парсера, вызываемого репозиторием.

**Результат шага 1:** script.js (или будущие модули) вызывают только `imageRepo.getAllPaths()`, `aboutRepo.getStudioAboutText()`, `aboutRepo.getProjectAbout(folderPath)`. Никаких прямых обращений к глобальному `imagePaths`, `ABOUT_TEXT` или `fetch(…about.txt)` в UI/логике.

---

### Шаг 2: Заменить прямые обращения к данным на вызовы репозиториев

**Цель:** Убрать из script.js (или выделенных модулей) все места, где используются «сырые» данные и подменить их вызовами репозиториев.

- Заменить использование `imagePaths` на вызовы `imageRepository.getAllPaths()` и при необходимости `getPathsByFolder(...)`. Инициализация `points`, загрузка изображений, фильтры и индексный режим должны опираться на эти методы.
- Заменить проверки `typeof ABOUT_TEXT !== 'undefined'` и использование `ABOUT_TEXT` на `aboutRepository.getStudioAboutText()`.
- Заменить вызовы `loadAndDisplayAboutText(folderPath)` на: получение данных через `aboutRepository.getProjectAbout(folderPath)` и существующие функции отображения (displayProjectAboutText / displayMobileAboutText), чтобы они принимали уже готовую структуру с name/about/fields.

**Результат шага 2:** В основной логике и UI нет глобальных констант списка картинок и about-текстов; все данные приходят через репозитории. Функциональность (поведение на экране) остаётся той же.

---

### Шаг 3: Вынести конфигурацию и при необходимости разбить script.js на модули

**Цель:** Сделать замену источника данных и конфигурации безопасной и локализованной.

- **Конфигурация:** Путь к корню проектов (`"Imgae test "`), базовые URL для fetch, лимиты загрузки (IMAGE_LOAD_CONCURRENCY, INITIAL_IMAGES_TO_LOAD и т.д.) вынести в один конфиг (объект или модуль config). Репозитории и загрузчики читают путь к папкам и настройки только из конфига.
- **Опционально — разбиение script.js:** По мере стабилизации можно выделить в отдельные модули:
  - загрузку и кэш изображений (используют ImageRepository);
  - отрисовку и анимации (читают state, не знают об источниках данных);
  - обработчики событий и режимы (вызывают репозитории и обновляют state/UI).

**Результат шага 3:** Замена источника изображений или формата about делается в одном месте (репозитории + конфиг). Поведение приложения не ломается, тесты можно писать на репозиториях и на логике, принимающей данные извне.

---

## Краткое резюме

| Проблема | Решение |
|----------|---------|
| Список картинок захардкожен в script.js | ImageRepository: getAllPaths(), при необходимости getPathsByFolder() |
| ABOUT_TEXT и fetch(about.txt) размазаны по коду | AboutRepository: getStudioAboutText(), getProjectAbout(folderPath) с парсингом внутри |
| Нет единого места для смены источника данных | Все доступы к данным только через репозитории |
| Сложно тестировать и менять | Репозитории можно мокать; конфиг и парсинг about — в одном месте |

После выполнения трёх шагов код готов к переносу в React (или другой фреймворк): репозитории можно переиспользовать как сервисы, а UI переписать на компоненты без дублирования логики данных.
